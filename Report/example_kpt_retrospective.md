## Keep (유지할 것)

이번 기간 동안 잘 되었고 계속 유지해야 할 것들:

- 매일 오전 10시 데일리 스탠드업 미팅이 효과적으로 진행되어 팀원 간 소통이 원활함
- 코드 리뷰 프로세스가 잘 정착되어 코드 품질이 향상됨
- Git 브랜치 전략(git-flow)을 일관되게 사용하여 버전 관리가 체계적으로 이루어짐
- 주간 회고를 통해 지속적인 개선 문화가 형성됨
- 문서화 작업이 실시간으로 업데이트되어 신규 팀원 온보딩이 수월함

## Problem (문제점)

이번 기간 동안 문제가 되었거나 개선이 필요한 것들:

- 배포 프로세스가 수동으로 이루어져 시간이 오래 걸리고 실수 가능성이 있음
- 테스트 커버리지가 60%로 낮아 버그 발생률이 높음
- API 문서가 최신 상태로 유지되지 않아 프론트엔드 팀과의 협업에 지연 발생
- 코드 머지 충돌이 자주 발생하여 개발 속도가 저하됨
- 프로젝트 일정 관리 도구(Jira) 사용이 일관되지 않아 진행 상황 파악이 어려움

---

## Try (시도할 것)

다음 기간에 시도해볼 것들 (Problem에서 도출된 개선 사항):

- CI/CD 파이프라인 구축하여 자동 배포 프로세스 도입
- 테스트 커버리지 80% 이상 달성을 위한 단위 테스트 작성 계획 수립
- Swagger/OpenAPI를 활용한 API 문서 자동화 도구 도입
- Git 브랜치 전략 개선 및 머지 전 충돌 검사 프로세스 추가
- Jira 사용 가이드라인 문서화 및 팀원 교육 실시
